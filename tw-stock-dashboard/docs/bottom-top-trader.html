03｜新增單筆已確認事件

手動事件必須來自你已確認的 TradingView 訊號；只寫一個 Bottom 不代表指標真的觸發。Trend 必須採已完成的上一根日 K 分數，不可使用未確認日線資料。

07｜指標對照與使用限制

原始指標進出場邏輯（直接保留）

Bottom = 已確認 K + 冷卻期通過 + 近期恐慌 (WVF) + 下跌極端動能 + 動能回升 + 反彈壓力門檻 + 選定盤態／時段；Top = 已確認 K + 冷卻期通過 + 貪婪尖峰 (GVF) + 上漲極端動能 + 動能走弱 + 回跌壓力 + 選定盤態／時段。Trend Score 使用上一根已完成日線，僅用在 B/C 的進場。

TOP、C 模型加碼與停損優先順序

同一事件如有 Top，先平倉，不補倉。若啟用緊急停損，觀測價格觸及限制則退出；之後才考慮 C 模型單次一批加碼。對每筆價格事件最多增加一批，不在沒有報價的時間段虛構成交。原始 Pine 會在訊號確認後使用下一根 K 開盤進場；本頁僅作訊號價紙上比較，兩者不能視為同一績效。

為何本頁沒有直接自動刷新 2 分鐘訊號？

GitHub Pages 是靜態網站，沒有受驗證的台股 2 分鐘 OHLCV 歷史源或 TradingView webhook 接收端。要做真正即時訊號，需要合規的行情來源／伺服器計算原始指標，或 TradingView alert → 有權限驗證的接收服務 → 前端 JSON。完成前不能冒充盤中自動交易雷達。此處先以原版 Pine 訊號 JSON/CSV 驅動。

研究用途，不自動下單；GitHub Pages 的前端存取密碼不能保護公開儲存的檔案，請勿在網站上傳或貼出券商帳號等機敏資料。
